# Bounded CUDA FMM qualification (2026-09-29)

The qualification probes ran before the narrow production CUDA gate change on an NVIDIA RTX 3060 Laptop GPU using Taichi 1.7.4, f32 precision, and a private 2% device pool. Probe source identity: FMM device SHA-256 `ec3d6f0a6f7d2edc984eed4e3b3d37e57a10fa77accdb81a78ed94180f4ae173`, LBVH SHA-256 `cd891287bbab83e43455f5ecc01e72fcd928ddbd45800b4ce2ed4c3a2f7d0e80`, acceptance tests SHA-256 `29e335049a5e7ddd6ab8006b5ae881c6129f851f6ac3ecbb6be2416908fb1e13`. The gate change only adds CUDA to the f32 FMM supported-device set; it does not change kernels, tolerances, or physical models.

The unchanged FMM numerical acceptance tests passed on CUDA for all four supported radial kernels (Gaussian, high-order Gaussian, super-Gaussian, Winckelmans), each with 512 near/far clustered sources, constant and varying core radii, direct-reference velocity/gradient/strength-rate bounds, active M2L and near interactions, and the existing strength-rate defect bound. A separate 64-source test passed permutation, translation, axis-rotation covariance, M2L, and L2L checks. Edge cases and hierarchy rebuild passed, as did 128-source batched arbitrary-target tests for Gaussian and Winckelmans. The first five checks completed before the first process's explicit 300 s cap; the remaining three completed in a second process with exit 0. Neither process reported a numerical failure. Exact per-gate durations and results are retained in `build/airfoil-mesh-verification/cuda-fmm-gates.json` and `cuda-fmm-remaining.json`.

A separate 64-source Gaussian probe had 2 M2L and 124 nonzero L2L operations with zero host particle transfers. Relative to direct evaluation, velocity, gradient, and strength-rate errors were `1.71e-7`, `1.63e-7`, and `1.16e-6`; 23 arbitrary targets had velocity and gradient errors `2.09e-5` and `3.93e-7`. A fresh-process queue-overflow probe failed hard before consuming an undersized logical interaction queue (`capacity=1`), as required. A process-local temporary support-gate extension allowed a native four-step CUDA FMM backup comparison: uninterrupted four steps and two steps plus backup/reload plus two steps produced bitwise-equal particle position, vortex strength, core radius, time `0.04 s`, and zero host particle transfers. That extension was never written to production source.

The new optional isolated GPU regression preserves the existing direct-reference thresholds and covers all four kernels, batched targets, queue overflow, and native backup replay. Its direct production-gate restart scenario passed after CUDA was added to `FMMInduction.supported_devices`: the real `VPMSolver` selected CUDA without a process-local support-gate override, and four uninterrupted accepted steps exactly matched two steps plus native backup/reload plus two steps. The probes do not measure production-size speedup, memory scaling, or every supported configuration; no acceleration claim follows from their wall times because CUDA compilation dominates these short runs. `AUTO` backend ordering was not changed.
